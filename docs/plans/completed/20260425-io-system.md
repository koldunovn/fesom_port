# IO System Overhaul for FESOM2 C Port

## Overview

Replace the current "one snapshot file per write" mechanism (`snap_NNNNNN.nc`
with placeholder time anchored to `1900-01-01`) with a proper time-mean IO
system that produces FESOM-style output and uses a single model-internal
calendar.

**Why now:** snapshots merge poorly because the per-file `time` is
`step_n × dt seconds since 1900-01-01`, which has no relation to the JRA55
forcing year actually being simulated. Production analysis wants
daily/monthly/yearly *means*, not snapshots, with CF-decoded dates that line
up with the forcing. The model also has three scattered re-implementations
of "what day/month is it?" — JRA55's `julday`, the static
`days_in_month[12]` non-leap array in `fesom_main.c:865`, and the
`month_now`/`update_monthly_flag` ad-hoc detection at `fesom_main.c:882-893`
— all of which become a single calendar struct.

**Scope deviation from port-fidelity rule:** the project rule is "literal
Fortran→C port, no simplification" (see `feedback_port_fidelity.md`). The
user has explicitly authorised this IO redesign as the documented exception:
"I am not suggesting to port FESOM2 exactly, we can make things better."
This plan calls out the deviation prominently and is bounded — it touches
IO + calendar consolidation only. Physics paths must remain bit-identical
(see Task 3 / Task 4 acceptance criteria).

**Final shape:**

- One `fesom_calendar_t` advanced once per step, consumed by JRA55, SSS/runoff,
  and IO. Three calendar kinds (proleptic Gregorian, 365-day no-leap, 360-day)
  selectable at run start, default Gregorian.
- Five output streams (`step` / `hourly` / `daily` / `monthly` / `yearly`).
  Mean for the latter four, instantaneous for `step`. Per-step accumulation
  is local-only (no MPI); flush gathers via the existing `gather_plan` and
  appends one record to an UNLIMITED `time` axis.
- FESOM-style file layout: one netCDF per (variable, period, cadence). E.g.
  `temp.fesom.1948.monthly.nc`. Year/month/day rollover depends on cadence.
- Default-on cadence: monthly only. The other four are opt-in via an override
  config file.
- Existing `fesom_io_write_snapshot` kept for ad-hoc debug dumps; it now
  takes the calendar so its `time` reflects the real run year.

### Patterns to follow (already established in the C port)

- **One C file per Fortran file** mirror does NOT apply here — IO is the
  documented exception. We're following netCDF/CF conventions instead.
- **Halo-write audit** still applies: any field a stream's `resolve()`
  callback returns must already be halo-exchanged at the point of access.
  After `fesom_timestep`, `dyn->uv`/etc. are exchanged; check each variable's
  resolver.
- **Build via `bash -l configure.sh`** as always (per
  `feedback_levante_build.md`). Never mambaforge.
- **Unique OUT_DIR per SLURM job** (per `feedback_unique_outdir_per_job.md`)
  still applies — new code keeps the rank-0-only-writes pattern.
- **Tracer storage stride is `nl`** (per `feedback_tracer_stride_nl.md`):
  3D node-tracer accumulators must be sized `[local_n × nl]`, not
  `[local_n × (nl-1)]`.

### Key invariants that must be preserved

- After Task 3+4 (JRA55 + SSS/runoff migrated to calendar), CORE2 1-day
  with PHC IC + JRA55 forcing must be **bit-identical** to a pre-overhaul
  reference run. The calendar is a name change, not a physics change.
- No new MPI calls in the per-step path. Stream `step()` is local memory
  ops only; gather happens at flush.
- `gather_plan` total_n / total_e invariants (Σmyn = nod2D, Σmye ≥ elem2D)
  hold for stream gathers, same as snapshot writer.

## Technical Details

### Calendar struct layout

```c
typedef enum {
    FESOM_CAL_GREGORIAN  = 0,   /* proleptic gregorian, leap years */
    FESOM_CAL_NOLEAP_365 = 1,
    FESOM_CAL_360_DAY    = 2,
} fesom_calendar_kind_t;

typedef enum {
    FESOM_PERIOD_STEP, FESOM_PERIOD_HOURLY, FESOM_PERIOD_DAILY,
    FESOM_PERIOD_MONTHLY, FESOM_PERIOD_YEARLY,
} fesom_period_kind_t;

typedef struct {
    fesom_calendar_kind_t kind;
    int    year, month, day;       /* 1-based, real values    */
    int    hour, minute;
    double second;
    int    origin_year, origin_month, origin_day;  /* CF anchor */
} fesom_calendar_t;
```

### Output kind + var kind

```c
typedef enum { FESOM_OUT_INSTANT, FESOM_OUT_MEAN } fesom_output_kind_t;

typedef enum {
    FESOM_VAR_2D_NODE,
    FESOM_VAR_3D_NODE_MID,     /* layer count = nl - 1, stored at stride nl */
    FESOM_VAR_3D_NODE_IFACE,   /* w, zbar  — nl interfaces                  */
    FESOM_VAR_2D_ELEM,
    FESOM_VAR_3D_ELEM_MID,
    FESOM_VAR_2D_ELEM_VEC,     /* uv: 2 components per element              */
} fesom_var_kind_t;
```

### File contents schema (per variable)

```
dimensions:
    time = UNLIMITED
    nbnds = 2
    nz_<X> = <appropriate count>            (only for 3D vars)
    nod2 = nod2D                            (or elem = elem2D)
variables:
    double time(time)
        :units = "seconds since YYYY-MM-DD 00:00:00"
        :calendar = "proleptic_gregorian" | "365_day" | "360_day"
        :bounds = "time_bnds"
    double time_bnds(time, nbnds)
    double lon(nod2), lat(nod2)
    double zbar(nz_nl) | Z(nz_nl_1)         (only for 3D vars; copied per file)
    double <var>(time, [nz_*,] nod2 | elem)
        :units, :long_name, :cell_methods = "time: mean" | (none for INSTANT)
attributes (global):
    :Conventions = "CF-1.8"
    :title = "FESOM2 C port — <var> <cadence>"
    :start_year, :calendar_kind          (for analysis convenience)
```

### Per-step cost model

- MEAN: `O(nvars × local_size)` adds; one `int` increment. No MPI.
- INSTANT (only `step` stream by default OFF): `O(nvars)` gathers + record-write per step. Used only when explicitly enabled.
- Flush: `O(nvars × local_size)` divide + `gather_plan` (one Gatherv per var) + ncwrite. For monthly at CORE2 dt=500, ~5180 steps between flushes → flush amortises to negligible.

### Override-file grammar (Task 8)

```
# Example io.config
sst        step,hourly,daily,monthly,yearly
ssh        monthly:instant,yearly
temp,salt  daily,monthly,yearly
u,v,w      monthly,yearly
```

Formal BNF:

```
file     := line*
line     := comment | blank | entry
comment  := '#' [^\n]* '\n'
blank    := [ \t]* '\n'
entry    := varlist  WSEP  cadlist  '\n'
varlist  := varname (',' varname)*       ; NO whitespace inside the list
cadlist  := cadence (',' cadence)*       ; NO whitespace inside the list
varname  := [A-Za-z_][A-Za-z0-9_]*
cadence  := period (':' kind)?
period   := 'step' | 'hourly' | 'daily' | 'monthly' | 'yearly'
kind     := 'instant' | 'mean'
WSEP     := [ \t]+                       ; one or more spaces/tabs, no commas
```

- Comments and blanks tolerated anywhere.
- One non-comment, non-blank line per entry.
- Multiple varnames per LHS allowed via comma; same for RHS cadences.
- Optional `:instant` / `:mean` suffix on each cadence; defaults: `step`→INSTANT, others→MEAN.
- Missing entry → compiled default (monthly MEAN) applies.
- **Whitespace inside a list (e.g. `temp, salt`) is a syntax error** — comma-separated lists are tightly bound. This is the disambiguation that lets the parser cleanly identify the LHS/RHS boundary by looking for the first whitespace run.
